01 / Problem

Job searching fragments across tabs, notes, resumes, reminders, and uncertain next actions.

JobTracker frames the problem as a personal CRM: one workspace for discovering leads, judging fit, converting opportunities, tracking applications, preparing interviews, managing materials, and deciding what deserves attention.

02 / Product Direction

Design-source compliance became the operating rule.

The alpha is governed by the current JobTracker design source and design system. New UI is not added casually; visible controls must map to source-backed behavior, documented alpha mocks, or explicit product decisions.

03 / Architecture

Supabase owns auth, data access, storage, and server-side integration boundaries.

The implementation uses RLS-backed tables, RPCs where workflows need stricter server control, storage for user materials, Edge Functions for sensitive provider and AI calls, and a client that does not hide configured backend errors.

04 / Delivery

Work is sliced vertically by visible user workflow.

Discovery, leads, pipeline, tasks, companies, materials, settings, onboarding, and auth are treated as complete behavior surfaces: empty states, validation, loading, success, failure, persistence, and responsive behavior are part of the slice.

05 / Verification

Regression checks protect source behavior and practical usability.

Playwright coverage targets actual interactions, no-horizontal-overflow checks, auth and onboarding flows, source setup, workspace CRUD, and UI states that commonly regress when product scope changes quickly.

06 / Roadmap

The next milestone is replacing approved alpha mocks with real backend behavior.

Remaining work focuses on provider hardening, richer source tracking, production email templates, resume parsing decisions, and public-readiness review before any source repository exposure.

Architecture Habits

The principles that govern system design and implementation.

01

Source-backed delivery

I turn design/product sources into implementation rules, route boundaries, source-compliance checks, and regression tests so UI does not drift silently.

02

Backend boundaries

I prefer explicit data ownership through Auth, RLS, RPCs, storage policies, and server-side integrations instead of pushing sensitive behavior into clients.

03

Alpha honesty

I keep mock behavior, unconfigured services, and deferred product decisions visible until they are replaced, accepted, or removed.
